Directories under original state root: image-inbox, image-tasks, image-media (0700), files0600. Producer writes binary plist atomically to image-inbox/<UUID>.plist:
{id:UUID,kind:'image',url:http(s) string,title:string,page:string,created:number,headers:{Referer,User-Agent},cookies:[NSHTTPCookie properties dictionaries]}.
Validate strictly, no arbitrary paths, max request file2MiB, bounded string sizes, UUID uniqueness; normalize NSHTTPCookie and only send matching secure/domain/path/nonexpired for target, recompute redirect cookies and Referer as needed, reject https downgrade. Requests only GET.
Consumer state image-tasks/<UUID>.plist (no secrets after saved): id,url,title,page,created,updated,state('queued','downloading','saving','saved','failed','uncertain'),received,total,error,assetID. Never include cookies in public task snapshot; internal persistence needed restart credentials use protected inbox/request separate internal file. Max concurrent downloads2, Photos saves serial. Session use ephemeral NSURLSession downloadTask (disk streaming). Data length bounded max100MiB. MIME/image validation via CGImageSourceCreateWithURL/GetType/GetCount, permit image types only reject HTML/empty/video, preserve downloaded image original bytes including animated GIF via PHAssetCreationRequest addResourceWithType:PHAssetResourceTypePhoto fileURL:. Verify pixel dimensions reasonable without full decode; title extension not trusted.
Photo permission add-only authorization; worker reused original private PhotosAdd entitlements. If no permission fail retaining file. Saving before Photos transaction persisted; crash saving -> uncertain and do NOT auto duplicate. Startup recovering downloading -> queued; failed requires explicit retry request (can omit retry functionality for v1 if documented but gallery should show failures). Photo library success removes local media and credentials, stores assetID and savedAt; failure keeps file and shows error.
