# Beta2 storage implementation / offline evidence

Implemented only `storage/Storage.m`, `tests/storage-beta2/{check.sh,io.c,mock.m}`, and this report. No original payload file was modified. No install, signing, Photos operation, or iOS execution was performed.

## Integration contract

Standalone ARC Foundation dylib, deployment iOS15. No PVXCommon or parent linkage. Parent adds LC_LOAD_DYLIB to original PyVideoAgent, preserving original LC_UUID, signs/packages, and keeps `.jbroot` resolution available. Gate is argv[0] leaf `PyVideoAgent`, MH_EXECUTE, UUID `F2FFAD31-EA7D-31F1-B189-241252297419`, full method return/argument type verification, and original C symbols located by dlsym with dladdr proving executable image ownership. MSHookMessageEx is dlsym-resolved; if absent, attempts executable-relative `.jbroot/usr/lib/libsubstrate.dylib` and `.jbroot/Library/Frameworks/CydiaSubstrate.framework/CydiaSubstrate`. If unavailable or ABI mismatch, no hooks are installed and original behavior remains; packaging must provide a working hook runtime. No new exported module API.

Root is original PVStateDirectory(), never a hardcoded mobile/rootless path. `plus-preferences.plist` must be binary plist and `autoSavePhotos` a CFBoolean. Missing file/key or invalid file/type defaults YES, aligned with parent. An explicit false suppresses exportReady before it calls Photos or changes ready state. Preference reads bounded to 16KiB. Poll fallback is 2 seconds with 0.5 second leeway on main queue; Darwin signal `com.crctdd.pyvideo.plus.storage` also triggers. It runs only in workerMode after reconciliation/memory policy permits exports. Existing in-flight Photos transactions complete even after the preference is switched off.

Manual command is binary `root/plus-manual-photos/<UUID>.plist` exactly `{id:<same UUID>, created:<Unix seconds NSNumber>}`. Filename must match id. Age accepted -60 seconds to +24 hours. Each pass examines at most 256 directory entries and processes at most 32 commands. Link-exclusive `.plist.claimed` marker precedes Photos authorization; original command is unlinked. Marker is removed after synchronous exportReady returns. A crash claim is not replayed automatically. Commands for downloading/local-processing tasks wait until ready. Only **ready** is eligible: saved/saving/albumFailed/uncertain/paused/deleting/unknown task requests are consumed without Photos. Parent UI must offer direct manual Photos only for ready. For albumFailed use the original explicit retry control first; uncertain requires its existing user-visible uncertainty handling and explicit retry, never implicit re-export. Current code does not turn albumFailed/uncertain into ready.

ExportReady's tasks getter has a thread-local one-task mutable dictionary view during the original synchronous call. Values are the original task records; real Agent.tasks is never replaced. The original Photos asynchronous completion looks up the full restored task table. No preference toggles or bulk-enable interval occur. Original export selection, permission checks, media selection, `mark:state:` write-failure behavior, exports set, Photos transaction ABI, and finishExport are reused intact.

Photos success while known exports membership + state saving + no clear request: retain the immutable original to `root/retained/<UUID>.mp4` via hard link first, directory fsync, then let original finalizer commit savedAt/assetID/state and unlink media. If original is absent, retain compatible instead. If hard link is unavailable, constant-memory 64KiB disk copy to exclusive staging + fsync + atomic no-overwrite link publication is used. Existing retained destinations must compare byte-identically. This copy fallback is synchronous on original main completion and can block for a large video; normal same-filesystem hard links avoid that cost. Leaf symlinks/empty/nonregular files are rejected. Input/output descriptors close and staging is removed on ordinary copy errors. Same source is immutable under original saving state; no network writer is active there.

Metadata is binary `retained/<UUID>.mp4.plist` via original PVWrite, fields id/source(original|compatible)/created and mediaBytes when present. Metadata is advisory; media publication is the success condition. Parent Files exporter should prefer retained, then original compatible/original media, as agreed. Hard-link retention does not preserve a second compatible full file. In the uncommon preexisting different-byte retained collision, publication is refused and originals are retained; parent should not treat such a conflicting retained file as verified from metadata alone.

If retention cannot complete (disk full, permission, collision), only the two exact original media paths are protected by a thread-local NSFileManager removal whitelist during this known successful finishExport callback. All other file operations forward unchanged; the whitelist restores in @finally. Original success still commits real savedAt/assetID, avoids Photos duplicate retry, and original/compatible files remain available as fallback. Failed Photos, uncertain/startup recovery, deletion and clear branches receive unchanged original finalization. No generic filesystem deletion suppression.

Explicit finishDeletion completion with task state deleted unlinks retained mp4/metadata. finishClearAll only removes retained UUID leaves after original clear barrier succeeded (clearingRequest cleared and tasks empty). Active/pending clear does not retain a new success copy. Original control:target: already dispatches finishDeletion, so no control hook is needed. Original files themselves were not patched; hooks affect `tasks`, `startWorker`, `exportReady`, `finishExport:success:error:assetID:`, `finishDeletion:`, `finishClearAll`, plus NSFileManager `removeItemAtPath:error:` with narrowly scoped fallback. No change to original Photos asset deletion behavior. Retained files persist until explicit task deletion/clear; no arbitrary disk quota eviction. Crash-stale copy staging or claims may require maintenance; they are not mistaken for tasks or Photos retries.
